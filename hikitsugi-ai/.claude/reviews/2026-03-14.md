### [✗] InputArea.tsx:27-37 — transcript クリアのタイミングによる入力消失バグ

**問題:**
`isListening` が `false` になると同時に `transcript` が残っている場合、`clearTranscript()` を呼ぶ。
しかし `onChange(transcript)` は同一レンダリングサイクル内で先に実行され、テキストエリアには値が入る。
問題は `continuous = false`（VoiceRecorder.tsx:85）のため、`onend` → `setIsListening(false)` の直後に
このeffectが走り、ユーザーが Enter を押す前に `clearTranscript()` → `onChange('')` が呼ばれ、
**入力が消える可能性がある。**

具体的な実行順序:
1. 音声認識完了 → `onresult` → `setTranscript("ユーザーの発話")`
2. `onend` → `setIsListening(false)`
3. React re-render: `useEffect([transcript, onChange])` → `onChange("ユーザーの発話")` ← OK
4. React re-render: `useEffect([isListening, transcript, clearTranscript])` → `clearTranscript()` → `setTranscript('')`
5. `useEffect([transcript, onChange])` が再度発火 → `onChange('')` ← **テキストが消える**

`clearTranscript` → `setTranscript('')` → `onChange('')` という連鎖が起きる。

**修正後のコード（InputArea.tsx 27-37行目を差し替え）:**

```tsx
// transcript が更新されたらテキストエリアに反映（録音中のみ）
useEffect(() => {
  if (!transcript) return
  onChange(transcript)
}, [transcript, onChange])

// 音声認識が終了したら transcript をクリア（onChange は呼ばない）
useEffect(() => {
  if (!isListening && transcript) {
    // transcript をクリアするだけ。onChange は呼ばない
    // ここで clearTranscript を呼ぶと onChange('') が再発火するため
    // clearTranscript は呼ばず、VoiceRecorder 側の state のみリセット
    clearTranscript()
  }
}, [isListening]) // transcript・clearTranscript を依存から外す
```

ただしこの修正だけでは不十分で、`VoiceRecorder.tsx` の `clearTranscript` 呼び出し後に
`transcript` が `''` になることで `useEffect([transcript, onChange])` 内の `if (!transcript) return` が
ガードとして機能するため、`onChange('')` は発火しない。
**よって `useEffect([isListening])` の依存配列から `transcript` と `clearTranscript` を除外する**のが正しい修正。

### [✗] InputArea.tsx:27-30 — transcript の上書き問題（ユーザーが手入力中に音声認識が割り込む）

**問題:**
ユーザーが手入力中に誤ってマイクボタンを押した場合、`onChange(transcript)` が `value` を
音声認識結果で完全上書きする。ユーザーの手入力が失われる。

`onChange(transcript)` ではなく、既存の `value` に `transcript` を追記する設計が適切。

**修正案:**
```tsx
useEffect(() => {
  if (!transcript) return
  // 既存テキストがあれば末尾に追記（スペース区切り）
  onChange(value ? `${value} ${transcript}` : transcript)
}, [transcript]) // value と onChange は意図的に除外（無限ループ防止）
```

### [△] VoiceRecorder.tsx:100-102 — interimResults で transcript が上書きされ finalText が失われる

**問題:**
`finalText || interimText` という評価式では、`finalText` が空文字列 `''` の場合（つまり
確定テキストがまだない間）は `interimText` を表示する。これは正しい。

しかし `continuous = false` の場合、複数の `onresult` イベントが来ることはほぼないため
実質的な問題は小さい。ただし `finalText` と過去のアキュムレーションが行われていないため、
複数ワードを一度に話した場合に中間の結果が捨てられる可能性がある。

現在:
```tsx
setTranscript(finalText || interimText)  // 常に最新の結果のみ
```

改善案（`continuous = true` に切り替えた際のための準備としても）:
```tsx
setTranscript(prev => {
  const newFinal = finalText
  const display = newFinal || interimText
  return display
})
```
※ `continuous = false` のままなら軽微。`continuous = true` に変える場合は要修正。

### [△] page.tsx:50-51 — `plan === 'team'` のハードコード

**問題:**
```tsx
const isPro = plan === 'pro' || plan === 'team'
```
`types.ts` には `ManualStatus` 等の型定義はあるが、`plan` の型定義がない。
`'team'` の他に `'team_s' | 'team_m' | 'team_l'` などの派生型が存在する場合（他プロジェクトの
MEMORY.md によれば MsgScore では `team_s / team_m / team_l` が存在する）、
このチェックが漏れる可能性がある。

**改善案:**
```tsx
// lib/types.ts に追加
export type UserPlan = 'free' | 'pro' | 'team'

// page.tsx
const isPro = plan !== 'free'
// または
const PRO_PLANS: UserPlan[] = ['pro', 'team']
const isPro = PRO_PLANS.includes(plan as UserPlan)
```

### [△] route.ts:52-58 — MIME typeバリデーションがバイパス可能

**問題:**
```tsx
const effectiveMimeType = mimeType || audio.type
if (!effectiveMimeType.startsWith('audio/')) { ... }
```
クライアントが `mimeType` フィールドを `'audio/evil'` と送り、
実際には悪意あるファイルを送付することができる。
`audio.type` はブラウザが送る `File.type` であり、これもクライアントコントロール下にある。

ただし Groq API 側でファイル内容をバリデーションするため、実害は限定的。
しかし防御の深さとして、許可リスト方式が推奨。

**改善案:**
```tsx
const ALLOWED_AUDIO_TYPES = [
  'audio/webm',
  'audio/mp4',
  'audio/mpeg',
  'audio/ogg',
  'audio/wav',
  'audio/flac',
  'audio/m4a',
]
if (!ALLOWED_AUDIO_TYPES.includes(effectiveMimeType)) {
  return NextResponse.json({ error: '対応していない音声形式です' }, { status: 400 })
}
```

### 修正1: InputArea.tsx — transcript クリアのタイミングバグ（旧行33-37 → 新行36-43）

**修正前:**
```tsx
// 音声認識が終了したら transcript をクリア
useEffect(() => {
  if (!isListening && transcript) {
    clearTranscript()
  }
}, [isListening, transcript, clearTranscript])
```

**修正後:**
```tsx
// 音声認識セッションが終了した時点で transcript をリセット
// transcript・clearTranscript を依存に含めないことで onChange 再発火（入力消失）を防ぐ
// eslint-disable-next-line react-hooks/exhaustive-deps
useEffect(() => {
  if (!isListening) {
    clearTranscript()
  }
}, [isListening])
```

`isListening` が `false` になった瞬間にのみ `clearTranscript` を呼ぶ。
`transcript` を依存に含めないため `transcript → onChange → clearTranscript → onChange('')` の
競合状態が防止される。

### 修正2: InputArea.tsx — 手入力テキストが音声認識で上書きされるバグ（旧行27-30 → 新行26-34）

**修正前:**
```tsx
// transcript が更新されたらテキストエリアに追記
useEffect(() => {
  if (!transcript) return
  onChange(transcript)  // ← value を完全上書きしていた
}, [transcript, onChange])
```

**修正後:**
```tsx
// transcript が更新されたらテキストエリアに反映（既存テキストがあれば末尾に追記）
// value を依存に含めると onChange → value 更新 → effect 再発火の無限ループになるため除外
// eslint-disable-next-line react-hooks/exhaustive-deps
useEffect(() => {
  if (!transcript) return
  // 既存の手入力テキストを保護しつつ音声認識結果を追記する
  const currentValue = textareaRef.current?.value ?? ''
  onChange(currentValue ? `${currentValue} ${transcript}` : transcript)
}, [transcript])
```

`textareaRef.current?.value` で DOM から直接現在値を読み取ることで、
`value` prop を依存に含めずに追記モードを実現。無限ループを回避しつつ
既存の手入力テキストを保護する。
